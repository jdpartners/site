# JDPartners 정책 문서

`policy.jdpartners.kr` 로 공개되는 정적 페이지(GitHub Pages, main 브랜치 그대로 게시).

글의 원본은 `src/` 의 마크다운 한 벌이다. 사람이 보는 페이지와 앱이 받는 파일을 `build.mjs` 가 그 원본에서 함께 만든다.
**생성물(`*.json`, `terms/`·`privacy/` 아래 `index.html`)은 손으로 고치지 않는다** — 고치면 화면의 글과 앱의 글이 갈린다.

| 주소 | 원본 | 용도 |
|---|---|---|
| `/<문서>/` | 가장 높은 버전 | 최신 문서(스토어·앱 소개에 적는 고정 주소) |
| `/<문서>/1/` | `src/<문서>/1.md` | 그 버전의 보관본 |
| `/<문서>/1/embed/` | 같은 파일 | **앱이 동의 화면에 띄우는 페이지**(상단 메뉴·목차·바닥글 없음) |
| `/<문서>/1.json` | 같은 파일 | 기록용 원문(마크다운) |
| `/`, `404.html`, `assets/` | 직접 편집 | 문서 목록·공용 스타일 |

문서는 다섯 종이다. 폴더 이름은 서버(PosProject 의 `PolicyDocument`)와 같아야 한다.

| 폴더 | 문서 | 누가 동의 |
|---|---|---|
| `terms` | 서비스 이용약관 | 가입한 모든 사람 |
| `privacy` | 개인정보 처리방침 | 가입한 모든 사람 |
| `processing-agreement` | 개인정보 처리 위탁계약서 | 매장 대표, 매장마다 |
| `subprocessor-consent` | 개인정보 재위탁 동의서 | 매장 대표, 매장마다 |
| `paid-service` | 유료서비스 이용 및 환불정책 | 매장 대표, 매장마다 |

## 버전
- 버전은 **서버와 같은 번호**다(`1`, `2` …). 서버는 `GET /api/config` 로 지금 유효한 버전을 알려 주고, 가입한 사람이 동의한 버전을 기록한다.
- 서버가 앱에 `/<문서>/<버전>/embed/` 주소를 내려주고 앱은 그 페이지를 그대로 띄운다. 그래서 **번호와 글이 한 쌍**이어야 한다.
- 머리말의 `changeSummary` 에 "이번 개정에서 바뀐 것"을 한두 문장으로 적으면 페이지 맨 위에 나온다 — 다시 동의받는 화면에서 사용자가 무엇이 바뀌었는지 본다. 첫 버전은 비운다.
- json 은 `{docType, version, title, effectiveDate, changeSummary, format, body}`. `effectiveDate` 가 `null` 이면 준비 중인 문서다.

## 고치는 법
```bash
npm install          # 처음 한 번
node build.mjs       # src 를 고친 뒤 실행 → 생성물 갱신
node build.mjs --check   # 생성물이 원본과 같은지 확인
```
- `src/<문서>/<버전>.md` 의 `작성 예정` 을 본문으로 바꾼다. 조 제목은 `## ` 로 시작한다(목차가 여기서 만들어진다).
- `[대괄호]` 는 아직 정해지지 않은 값이다(시행일, 사업자 정보, 보호책임자, 업체 계약 법인 등). **대괄호가 남은 문서는 시행하지 않는다.**
- `<!-- … -->` 주석은 쓰는 사람을 위한 메모이고 어디에도 게시되지 않는다.
- 받은 원문에서 무엇을 왜 바꿨는지, 기능을 추가할 때 어느 조항을 고쳐야 하는지는 PosProject 의 `docs/policy-documents.md` 에 있다.
- 원본과 생성물을 **같은 커밋에** 올린다.
- 하단 사업자 정보(`TODO`)는 `build.mjs` 의 바닥글과 `index.html`·`404.html` 에 있다.

## 시행할 때
1. 머리말의 `effectiveDate:` 에 `YYYY-MM-DD` 를 적고 빌드한다. "준비 중" 안내와 검색 차단이 함께 사라진다.
2. `index.html`·`404.html` 의 `<meta name="robots" content="noindex">` 줄을 지운다.
3. **시행일을 적은 버전은 그 뒤로 한 글자도 고치지 않는다** — 그 버전에 동의한 사람이 본 글이다. 오타도 다음 버전에서 고친다.

## 개정할 때
1. `src/<문서>/2.md` 를 새로 만든다(앞 버전을 복사해 `version: 2`, 새 시행일). 개정 이력 조에 바뀐 내용을 적는다.
2. 빌드하고 올린다. `/<문서>/2.json` 이 열리는지 확인한다.
3. **그다음에** 서버의 `POLICY_<문서>_VERSION` 을 올린다. 순서가 바뀌면 앱이 없는 페이지를 연다.
4. 다시 동의받아야 하는 개정(불리한 변경, 위탁 업체 변경)이면 서버의 `POLICY_<문서>_REQUIRED_VERSION` 과
   `POLICY_<문서>_REQUIRED_FROM`(시행일)도 함께 올린다. 가벼운 개정은 3번까지만 — 앱이 알림만 띄운다.
